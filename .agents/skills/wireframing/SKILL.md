# 線框圖設計法則

## 核心價值

線框圖是介面設計的骨架,聚焦於資訊層級、內容佈局與互動邏輯,排除視覺干擾。有效的線框圖能快速驗證設計假設、促進團隊溝通,並在投入高成本開發前發現結構性問題。

## 適用情境

- 概念發想和快速迭代階段
- 與團隊討論介面結構時
- 在投入高保真設計前驗證想法
- 向利害關係人展示初步構想時

## 輸入資訊

- 頁面目標與核心任務
- 必要功能與內容區塊
- 使用者流程或導航結構
- 平台尺寸需求
- 需要溝通或驗證的重點

## 預期產出

- 線框圖範圍與層級規劃
- 主要版面與區塊配置
- 基本互動標註
- 不同保真度的建議做法
- 可供討論與迭代的初版方案

## 觸發提示

- 使用者提到「線框圖」、「wireframe」、「頁面草圖」、「低保真」、「版面配置」
- 任務需要先快速確認畫面結構與內容優先順序
- 任務需要在正式視覺設計前先討論頁面骨架

## 複雜情境觸發提示

- 任務涉及 B2B 後台、管理介面、資料密集頁面或跨角色操作流程
- 使用者提到儀表板、審核台、設定中心、權限管理、報表或多步驟表單
- 問題包含資訊過多、欄位複雜、操作順序不清楚或角色之間使用同一頁面但需求不同
- 團隊需要先快速把複雜業務流程轉成可討論的頁面骨架與區塊配置

## 先問哪些澄清問題

- 這個頁面的主要任務是什麼?成功完成後代表什麼業務結果?
- 主要使用者是誰?是否還有其他角色會看同一畫面?
- 畫面上必須出現哪些資訊、欄位、操作與狀態?
- 哪些資訊要優先看見?哪些是進階或低頻資訊?
- 這個流程是否有審批、例外處理、批次操作或權限差異?
- 這份線框圖是用來對齊需求、驗證流程還是準備進一步做原型?

## 可搭配哪些其他 skill

- `information-architecture`: 先整理內容層級與導航再畫線框圖
- `prototyping`: 將線框圖延伸為可測試的互動流程
- `usability-testing`: 用線框圖或原型驗證操作是否清楚
- `design-system`: 讓線框圖更容易對應後續元件與版型規範

## 複雜需求範例

### B2B 後台儀表板

- 情境: 管理者需要同時查看 KPI、待處理事項、異常警示與團隊狀態
- Wireframe 重點: 區分總覽資訊、優先行動區與詳細分析入口,避免首頁過載

### 多角色審批頁面

- 情境: 同一申請頁面會被申請人、審核者與主管使用
- Wireframe 重點: 呈現不同角色看到的資訊區塊、審批記錄與下一步操作

### 複雜設定中心

- 情境: SaaS 管理後台包含帳號、權限、通知、整合與計費設定
- Wireframe 重點: 建立清楚的分群、次層導航與危險操作提示

## 工作流程

### 1. 定義目標

**明確頁面目的**
```markdown
頁面目標範例:
- 頁面: 產品詳情頁
- 主要目標: 讓使用者了解產品並加入購物車
- 次要目標: 展示相關產品推薦
- 成功指標: 加入購物車轉換率
```

**列出必要元素**
- 導航列
- 產品圖片
- 產品名稱和價格
- 產品描述
- 規格選擇
- 加入購物車按鈕
- 相關產品

### 2. 參考視覺風格 (可選)

**選擇設計風格參考**

即使是低保真線框圖,也可以先確認視覺風格方向,避免後期大幅調整。

```markdown
參考資源:
- StylePrompts 設計風格庫: https://styleprompt.zeabur.app/
- 101 種專業設計風格可供參考
- 根據產品類型快速選擇適合的風格方向

建議:
- 瀏覽 2-3 個相關風格
- 注意佈局方式、資訊層級、留白比例
- 不需要在線框圖階段處理色彩與細節
- 重點是確認整體風格方向(極簡/豐富、緊湊/寬鬆)
```

**何時需要參考風格?**
- 新產品或重新設計時
- 需要向利害關係人展示方向時
- 團隊對視覺方向有疑慮時
- 想要快速建立專業感時

### 3. 繪製草圖

**紙筆快速草圖**
```markdown
優點:
✓ 速度最快
✓ 容易修改
✓ 適合團隊腦力激盪
✓ 降低執著於細節的風險

工具:
- A4 白紙或方格紙
- 鉛筆或黑筆
- UI 模板紙 (可選)
```

**數位工具繪製**
```markdown
推薦工具:
- Figma (協作友善)
- Sketch (Mac 專用)
- Balsamiq (低保真專用)
- Whimsical (快速簡單)
- Excalidraw (手繪風格)
```

### 4. 確定佈局

**常見佈局模式**

**F 型佈局**
```
[Logo]  [導航列]
[大標題]
[內容內容內容]
[內容] [側邊欄]
[內容] [側邊欄]
```

**Z 型佈局**
```
[Logo] ----------> [CTA按鈕]
       ↘
[特色內容]
       ↘
[詳細說明] -----> [註冊表單]
```

**卡片式佈局**
```
[卡片1] [卡片2] [卡片3]
[卡片4] [卡片5] [卡片6]
```

**柵格系統**
```markdown
常用柵格:
- 12 欄柵格 (最常見)
- 8 欄柵格 (平板)
- 4 欄柵格 (手機)

間距:
- 欄間距: 20-30px
- 外邊距: 20-40px
```

### 5. 標註說明

**互動標註**
```markdown
[按鈕]
→ 點擊後: 開啟彈出視窗
→ 狀態: 預設 / Hover / 點擊 / 禁用

[下拉選單]
→ 選項: 選項A, 選項B, 選項C
→ 預設值: 請選擇

[輸入框]
→ 提示文字: 請輸入電子郵件
→ 驗證: 必填,格式檢查
→ 錯誤訊息: 請輸入有效的電子郵件
```

**內容說明**
```markdown
[圖片區塊]
→ 尺寸: 800x600px
→ 內容: 產品主圖
→ 替代文字: 產品名稱

[文字區塊]
→ 標題: H1, 32px
→ 內容: 2-3 段落
→ 字數: 約 150 字
```

### 5. 團隊審查

**審查檢查清單**
```markdown
□ 資訊層級是否清晰?
□ 主要 CTA 是否明顯?
□ 導航是否直觀?
□ 內容佈局是否合理?
□ 響應式設計考慮?
□ 無障礙性考慮?
□ 與品牌一致性?
```

### 7. 迭代優化

**收集回饋**
- 與設計師討論視覺可行性
- 與開發者討論技術可行性
- 與產品經理確認功能完整性
- 與使用者測試可用性

**快速調整**
- 根據回饋立即修改
- 繪製多個版本比較
- 不要過早追求完美

## 快速執行指南

**1 小時快速版**
1. 定義頁面目標 (10 分鐘)
2. 紙筆快速草圖 3 個版本 (20 分鐘)
3. 選擇最佳方案並數位化 (20 分鐘)
4. 加入基本標註 (10 分鐘)

**完整版 (建議)**
1. 定義目標與收集需求 (1 小時)
2. 參考視覺風格(如需要) (30 分鐘)
3. 繪製多個草圖版本 (2 小時)
4. 確定佈局與網格 (1.5 小時)
5. 標註說明 (1 小時)
6. 團隊審查與迭代 (2 小時)

**決策樹: 何時使用哪個版本?**
- 簡單頁面 + 快速驗證想法 → 快速版
- 複雜介面或關鍵頁面 → 完整版
- 需要交付給開發團隊 → 完整版 + 詳細標註

## 最佳實踐

1. **保持簡單**: 使用灰階和基本形狀
2. **專注功能**: 專注於功能和內容,而非視覺美感
3. **清楚標示**: 標示清楚互動元素和狀態
4. **保持一致**: 保持一致的元件使用
5. **快速迭代**: 快速迭代,不要過早追求完美
6. **真實內容**: 使用真實內容而非 Lorem Ipsum
7. **考慮響應式**: 繪製不同螢幕尺寸的版本

## 線框圖保真度層級

### 低保真 (Lo-Fi)
```markdown
特徵:
- 手繪或簡單方框
- 無細節
- 快速草圖

適用:
- 初期概念發想
- 快速腦力激盪
- 多方案比較
```

### 中保真 (Mid-Fi)
```markdown
特徵:
- 數位工具繪製
- 有基本佈局
- 灰階呈現

適用:
- 與團隊溝通
- 使用者測試
- 開發參考
```

### 高保真 (Hi-Fi)
```markdown
特徵:
- 接近最終設計
- 有真實內容
- 可能有顏色

適用:
- 最終確認
- 客戶提案
- 開發交付
```

## 常見元素符號

```markdown
文字內容:
─────── (標題)
....... (段落文字)

互動元素:
[按鈕]
[_____] (輸入框)
[▼] (下拉選單)
□ (核取方塊)
○ (單選按鈕)

媒體:
[IMAGE] (圖片)
[▶] (影片)
[🔊] (音訊)

圖示:
☰ (選單)
🔍 (搜尋)
🛒 (購物車)
❤ (收藏)
⚙ (設定)
```

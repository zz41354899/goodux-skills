# Skills 系統測試情境

用於測試 AI Agent 是否能正確推薦 skill、避免錯亂、檢測專案狀態。

---

## 測試情境 1：全新專案（應推薦 Empathize）

### 使用者問題
```
我想做一個電商網站的結帳流程優化專案
```

### 預期 AI 回應
1. 詢問是否已有使用者研究
2. 推薦 `/empathize`
3. 說明原因：需要先了解使用者結帳習慣與痛點

### 測試重點
- ✅ 正確判斷為全新專案
- ✅ 推薦 Empathize 而非直接設計
- ✅ 說明推薦理由

---

## 測試情境 2：有研究無定義（應推薦 Define）

### 使用者問題
```
我已經訪談了 8 位使用者，發現他們在結帳時常常放棄，
主要痛點是付款選項太複雜、運費不透明。
接下來該怎麼做？
```

### 預期 AI 回應
1. 確認已有使用者研究
2. 推薦 `/define`
3. 說明：需要定義核心問題、成功指標、MVP 範圍

### 測試重點
- ✅ 識別已有研究資料
- ✅ 不重複推薦 Empathize
- ✅ 推薦 Define 收斂問題

---

## 測試情境 3：關鍵字衝突（測試/設計）

### 使用者問題
```
我想測試一下這個結帳流程的設計方向
```

### 預期 AI 回應
1. 詢問：是否已有設計稿或原型？
2. 根據回答推薦：
   - 無設計稿 → `/ideate`（先設計）
   - 有設計稿無原型 → `/prototype`（先做原型）
   - 有原型 → `/test`（直接測試）

### 測試重點
- ✅ 識別關鍵字衝突（測試 + 設計）
- ✅ 詢問專案狀態
- ✅ 根據狀態推薦單一 skill

---

## 測試情境 4：開發選項詢問（Ideate 完成）

### 使用者問題
```
我完成了結帳流程的線框圖設計，
包含單頁結帳和兩段式結帳兩個方案
```

### 預期 AI 回應
1. 確認 Ideate 完成
2. 詢問開發選項：
   - A. 用程式碼實作（React + Shadcn/UI）
   - B. 先做設計工具原型（Figma）
   - C. 自訂技術架構
   - D. 略過（繼續設計）
3. 等待使用者選擇

### 測試重點
- ✅ 識別 Ideate 完成
- ✅ 提供開發選項
- ✅ 允許使用者略過

---

## 測試情境 5：跳階段請求（應提醒前置條件）

### 使用者問題
```
直接幫我設計一個結帳頁面
```

### 預期 AI 回應
1. 詢問前置條件：
   - 是否已了解使用者結帳習慣？
   - 是否已定義結帳頁面的成功指標？
2. 提供選項：
   - A. 快速版：基於常見模式設計（風險：可能不符需求）
   - B. 完整版：先研究再定義再設計（推薦）
3. 尊重使用者選擇

### 測試重點
- ✅ 識別缺少前置條件
- ✅ 提供快速版與完整版選項
- ✅ 說明風險

---

## 測試情境 6：測試後迭代（應分級問題）

### 使用者問題
```
我測試了結帳原型，發現使用者找不到優惠碼輸入框，
而且付款按鈕的對比度不足
```

### 預期 AI 回應
1. 分析問題嚴重度：
   - 找不到優惠碼 → P1（嚴重影響體驗）
   - 對比度不足 → P1（a11y 問題）
2. 推薦迭代方式：
   - 回到 `/ideate` 重新設計優惠碼位置
   - 調整按鈕對比度（局部修正）
3. 說明優先順序

### 測試重點
- ✅ 正確分級問題（P0-P3）
- ✅ 推薦適當的迭代方式
- ✅ 說明優先順序

---

## 測試情境 7：多 Skill 同時觸發（應選擇單一）

### 使用者問題
```
我想設計並測試一個新的結帳流程原型
```

### 預期 AI 回應
1. 識別多個關鍵字：設計（Ideate）、原型（Prototype）、測試（Test）
2. 詢問專案狀態：目前有設計稿嗎？
3. 推薦單一 skill：
   - 無設計 → `/ideate`
   - 有設計 → `/prototype`
   - 有原型 → `/test`
4. 說明：完成後可依序進行下一階段

### 測試重點
- ✅ 識別多 skill 衝突
- ✅ 只推薦一個 skill
- ✅ 說明順序流程

## 測試情境 8：選擇 React 開發（應提供技術指引）

### 使用者對話

2. 說明技術架構：
   - React 18 + Next.js 14
   - Shadcn/UI + Tailwind CSS
   - TypeScript
3. 提供快速啟動指令
4. 詢問是否開始實作

### 測試重點
- ✅ 識別開發選項選擇
- ✅ 提供技術架構說明
- ✅ 提供實作指引

## 測試情境 9：既有專案改版（應判斷階段）

### 使用者問題
```
我們的電商網站結帳流程需要改版，
使用者反應不好用，但我們不確定具體問題在哪
```

### 預期 AI 回應
1. 識別為既有產品改版
2. 詢問：是否已知道「哪裡」不好用？
3. 推薦：
   - 不知道問題 → `/test`（先找出問題）
   - 知道問題不知原因 → `/empathize`（了解原因）
   - 知道問題和原因 → `/define`（定義改版範圍）

### 測試重點
- ✅ 識別既有專案改版情境
- ✅ 根據問題明確度推薦
- ✅ 說明推薦理由

---

## 測試情境 10：模糊需求（應澄清）

### 使用者問題
```
我想改善產品
```

### 預期 AI 回應
1. 澄清問題：
   - 想改善什麼？（功能/體驗/視覺）
   - 為什麼要改善？（數據/回饋/假設）
   - 目前有什麼問題？
2. 等待使用者回答
3. 根據回答推薦對應 skill

### 測試重點
- ✅ 識別模糊需求
- ✅ 主動澄清
- ✅ 不直接猜測推薦

## 快速測試檢查清單

## 預期輸出範例

### 範例 1：Empathize 推薦
```markdown
根據您的需求，建議使用 `/empathize` 技能。

**原因**：
- 這是全新的結帳流程優化專案
- 需要先了解使用者的結帳習慣與痛點
- 避免基於假設設計

**下一步**：
1. 規劃使用者訪談
2. 招募 6-8 位目標使用者
3. 整理痛點與洞察

您想要開始使用者研究嗎？
```

### 範例 2：開發選項詢問
```markdown
太好了！完成線框圖設計後，您想要：

**選項 A：用程式碼實作（React + Shadcn/UI）**
- 可立即測試真實互動
- 驗證技術可行性

**選項 B：先做設計工具原型（Figma/Axure）**
- 快速迭代，不需寫程式
- 適合設計階段

**選項 C：自訂技術架構**
- 告知您的技術偏好

**選項 D：略過（繼續設計）**

您偏好哪個選項？
```

## 使用方式

1. **複製測試情境**到 AI 對話中
2. **觀察 AI 回應**是否符合預期
3. **記錄問題**並調整關鍵字或規則
4. **重複測試**直到所有情境通過

# 互動原型製作技能

## 技能摘要

互動原型是具有真實互動功能的產品模擬,讓使用者能夠點擊、滑動和操作,體驗接近最終產品的流程。這是驗證設計和收集回饋的有效工具。

## 適用情境

- 需要測試複雜的互動流程時
- 向利害關係人展示設計概念時
- 在開發前驗證技術可行性時
- 進行可用性測試時

## 輸入資訊

- 產品目標或功能目標
- 主要使用者流程
- 頁面清單或畫面需求
- 互動細節、狀態與邊界情境
- 測試目的或展示目的

## 預期產出

- 原型範圍定義
- 畫面與狀態清單
- 互動流程與轉場規格
- 原型製作建議與工具選擇
- 測試與迭代建議

## 觸發提示

- 使用者提到「原型」、「prototype」、「flow」、「點擊流程」、「轉場」、「高保真」
- 任務需要把線框圖升級成可測試或可展示的互動版本
- 任務需要整理互動狀態、動畫回饋或操作邏輯

## 複雜情境觸發提示

- 任務涉及 B2B 後台、管理流程、多步驟設定、審批機制或跨角色協作流程
- 使用者提到需要模擬多種狀態、權限差異、例外流程、批次操作或跨頁操作邏輯
- 問題不只是單一畫面,而是整段工作流程是否順暢、可理解、可展示或可測試
- 團隊需要在開發前先驗證複雜流程、說服利害關係人或對齊多部門理解

## 先問哪些澄清問題

- 這個原型的主要目的是測試、展示、對齊需求還是交付開發?
- 需要涵蓋哪些關鍵角色、步驟、分支流程與例外狀態?
- 哪些互動細節一定要模擬?例如權限限制、審批退回、錯誤訊息或批次處理
- 原型要做到什麼保真度才足以回答目前的決策問題?
- 利害關係人最想驗證的是流程、內容理解、操作效率還是視覺可信度?
- 原型完成後會如何驗證?會做可用性測試、內部評審還是客戶展示?

## 可搭配哪些其他 skill

- `wireframing`: 先定義頁面骨架與資訊優先順序
- `usability-testing`: 用原型驗證複雜流程是否可理解
- `design-system`: 提升原型一致性並對應後續實作元件
- `information-architecture`: 若流程涉及多模組與深層導航,先整理結構

## 複雜需求範例

### B2B onboarding 原型

- 情境: 新客戶管理員需要完成帳號建立、資料匯入、權限設定與團隊邀請
- Prototype 重點: 模擬完整步驟、錯誤狀態、進度提示與返回編輯流程

### 後台審批與退件流程

- 情境: 審核員、主管與申請人會在不同節點看到不同資訊與操作
- Prototype 重點: 模擬狀態切換、退回原因、審批記錄與角色視角差異

### 多角色報表工作流

- 情境: 分析師建立報表、主管審閱、營運追蹤異常並指派處理
- Prototype 重點: 呈現資料篩選、異常追蹤、通知回饋與後續行動入口

## 工作流程

### 1. 選擇工具

**工具比較**
```markdown
Figma:
✓ 協作友善
✓ 基本互動功能
✓ 免費方案
✓ 瀏覽器執行
- 複雜動畫有限

Protopie:
✓ 進階互動
✓ 感應器支援
✓ 條件邏輯
- 需要付費
- 學習曲線較陡

Framer:
✓ 程式碼整合
✓ 真實元件
✓ 進階動畫
- 需要程式基礎

Principle:
✓ 動畫專精
✓ 時間軸編輯
- Mac 專用
- 功能較單一

Adobe XD:
✓ Adobe 生態系
✓ 自動動畫
- 發展較慢
```

**選擇建議**
```markdown
基本互動 → Figma
進階互動 → Protopie
動畫重點 → Principle
程式整合 → Framer
```

### 2. 設計畫面

**畫面清單**
```markdown
範例: 電商 App 結帳流程

必要畫面:
1. 購物車頁面
2. 配送資訊頁面
3. 付款方式頁面
4. 訂單確認頁面
5. 完成頁面

狀態畫面:
- 空購物車狀態
- 載入中狀態
- 錯誤狀態
- 成功狀態
```

**設計規範**
```markdown
保真度選擇:
- 低保真: 灰階線框圖
- 中保真: 基本視覺設計
- 高保真: 完整視覺設計

內容:
✓ 使用真實內容
✓ 準備多種狀態
✓ 考慮邊界情況
❌ 避免 Lorem Ipsum
```

### 3. 加入互動

**基本互動類型**

**點擊 (Tap/Click)**
```markdown
觸發器: 點擊按鈕
動作: 導航到下一頁
過渡: 向左滑入

範例:
[加入購物車] 按鈕
→ 點擊後
→ 顯示成功提示
→ 購物車數量 +1
```

**滑動 (Swipe)**
```markdown
觸發器: 向左滑動
動作: 顯示刪除按鈕
過渡: 滑動動畫

範例:
商品卡片
→ 向左滑動
→ 顯示 [刪除] 按鈕
→ 點擊刪除
→ 卡片淡出
```

**拖曳 (Drag)**
```markdown
觸發器: 拖曳元素
動作: 移動位置
約束: 限制範圍

範例:
滑桿控制
→ 拖曳滑塊
→ 更新數值
→ 即時反饋
```

**輸入 (Input)**
```markdown
觸發器: 輸入文字
動作: 即時驗證
回饋: 顯示提示

範例:
電子郵件輸入
→ 輸入文字
→ 格式檢查
→ 顯示錯誤/成功
```

### 4. 建立流程

**使用者流程**
```markdown
註冊流程範例:

1. 啟動畫面
   ↓ [開始使用]
2. 輸入電子郵件
   ↓ [繼續]
3. 輸入密碼
   ↓ [繼續]
4. 個人資料
   ↓ [完成註冊]
5. 驗證電子郵件
   ↓ [已驗證]
6. 完成畫面

分支流程:
- 電子郵件已存在 → 顯示錯誤
- 密碼不符規則 → 顯示提示
- 驗證逾時 → 重新發送
```

**互動地圖**
```markdown
首頁
├─ [搜尋] → 搜尋結果頁
├─ [分類] → 分類列表頁
│   └─ [商品] → 商品詳情頁
│       ├─ [加入購物車] → 購物車頁
│       └─ [立即購買] → 結帳頁
└─ [購物車] → 購物車頁
    └─ [結帳] → 結帳頁
        ├─ 配送資訊
        ├─ 付款方式
        └─ 訂單確認
            └─ [確認訂單] → 完成頁
```

### 5. 加入動畫

**動畫類型**

**過渡動畫**
```markdown
頁面切換:
- 向左滑入 (前進)
- 向右滑出 (返回)
- 淡入淡出 (Modal)
- 由下往上 (Sheet)

時間: 300-400ms
緩動: ease-in-out
```

**微互動**
```markdown
按鈕點擊:
- 縮放效果 (0.95x)
- 顏色變化
- 漣漪效果

載入中:
- 旋轉動畫
- 骨架屏
- 進度條

成功/錯誤:
- 勾選動畫
- 震動效果
- 顏色變化
```

**進階動畫**
```markdown
視差滾動:
- 背景慢速移動
- 前景快速移動
- 創造深度感

物理動畫:
- 彈跳效果
- 慣性滑動
- 橡皮筋效果

手勢動畫:
- 下拉重新整理
- 滑動刪除
- 捏合縮放
```

### 6. 測試調整

**自我測試**
```markdown
檢查清單:
□ 所有連結都有效
□ 返回按鈕正常運作
□ 動畫流暢不卡頓
□ 載入狀態完整
□ 錯誤狀態處理
□ 邊界情況考慮
□ 手機/平板都測試
```

**使用者測試**
```markdown
觀察重點:
- 使用者是否理解互動
- 是否能順利完成任務
- 哪裡感到困惑
- 動畫是否過多/過少
- 回饋是否清楚

調整方向:
- 簡化複雜流程
- 加強視覺回饋
- 優化動畫時間
- 改善錯誤處理
```

## 最佳實踐

1. **適當保真度**: 根據測試目標決定保真度層級
2. **聚焦流程**: 專注於關鍵流程,不需要完整產品
3. **真實內容**: 使用真實內容而非假資料
4. **一致互動**: 保持互動的一致性
5. **完整狀態**: 加入適當的載入和錯誤狀態
6. **記錄限制**: 記錄原型的限制和假設
7. **效能考量**: 避免過度複雜的動畫

## 原型保真度

### 低保真原型
```markdown
特徵:
- 灰階線框圖
- 基本點擊互動
- 無動畫

適用:
- 早期概念驗證
- 流程測試
- 快速迭代

工具: Figma, Balsamiq
```

### 中保真原型
```markdown
特徵:
- 基本視覺設計
- 頁面過渡
- 簡單動畫

適用:
- 可用性測試
- 團隊溝通
- 客戶提案

工具: Figma, Adobe XD
```

### 高保真原型
```markdown
特徵:
- 完整視覺設計
- 複雜互動
- 進階動畫
- 真實資料

適用:
- 最終驗證
- 開發交付
- 投資者展示

工具: Protopie, Framer
```

## 進階技巧

### 條件邏輯
```markdown
範例: 根據輸入顯示不同內容

IF 選擇「信用卡」
  THEN 顯示信用卡欄位
ELSE IF 選擇「貨到付款」
  THEN 顯示提醒訊息
```

### 變數使用
```markdown
範例: 購物車數量

變數: cartCount = 0

點擊 [加入購物車]
→ cartCount = cartCount + 1
→ 更新購物車圖示數字
```

### 元件狀態
```markdown
按鈕元件:
- Default (預設)
- Hover (懸停)
- Pressed (按下)
- Disabled (禁用)
- Loading (載入中)

使用 Variants 管理所有狀態
```
